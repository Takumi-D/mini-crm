# Стройконтроль — мини-CRM

React + TypeScript + Supabase. В приложении есть рабочая область постановщика и исполнителя, список объектов и задач, карточка задачи с историей, а также переходы по заданному жизненному циклу.

## Структура приложения

- `src/lib/supabase.ts` настраивает единственный клиент Supabase.
- `src/lib/api.ts` содержит функции запросов к Supabase. Компоненты и хуки не строят запросы напрямую.
- `src/hooks/useAuth.ts` управляет сессией, входом и выходом.
- `src/hooks/useProfile.ts` загружает профиль пользователя и список исполнителей для постановщика.
- `src/hooks/useProjects.ts` загружает объекты и предоставляет их CRUD-операции.
- `src/hooks/useTasks.ts` загружает задачи и историю, выполняет CRUD-операции и переходы статусов.
- `src/components/WorkspaceLayout.tsx` отвечает за боковую навигацию и верхнюю панель.
- `src/components/ProjectsPage.tsx` отображает обзор объектов и сводные показатели.
- `src/components/TasksPage.tsx` отображает задачи объекта или личный список исполнителя.
- `src/components/StatusMessages.tsx` показывает сообщения об ошибках и успешных действиях.
- Остальные компоненты отвечают за карточки, формы и диалоги.
- `src/App.tsx` собирает хуки и компоненты, выбирает экран и связывает действия пользователя с нужными хуками.

## Запуск

1. В Supabase откройте SQL Editor, вставьте содержимое `supabase/schema.sql` и запустите его.
2. В Authentication → Settings отключите публичную регистрацию (Enable Sign ups). Создайте пользователей вручную в Authentication → Users.
3. Для каждого пользователя добавьте профиль, используя его UUID из Authentication → Users:

   ```sql
   insert into public.profiles (id, full_name, role)
   values ('UUID_ИЗ_AUTH_USERS', 'Имя Фамилия', 'manager');
   ```

   Роль должна быть `manager` или `executor`. Повторите для остальных пользователей.

4. Скопируйте `.env.example` в `.env.local`, укажите URL проекта и publishable key из Supabase → Project Settings → API Keys.
5. Установите зависимости и запустите приложение:

   ```sh
   npm install
   npm run dev
   ```

Не вставляйте secret/service_role key в `.env.local`, код приложения или репозиторий. Клиент использует только publishable key; доступ ограничен RLS.

Если вы уже запускали предыдущую версию схемы, вместо повторного запуска `schema.sql` примените миграции из `supabase/migrations/` по порядку. Первая включает редактирование и удаление, вторая разрешает защищённой функции workflow менять статус задачи, сохраняя запрет на прямое изменение через API.

## Модель безопасности

- RLS ограничивает исполнителя его задачами и связанными объектами. Постановщик видит рабочее пространство целиком.
- Создание задачи и переходы статуса выполняются функциями базы с проверкой роли, назначенного исполнителя и текущего статуса.
- История создается триггером при появлении задачи и функций перехода. Изменить или удалить историю напрямую нельзя.
- Обычное изменение защищенных полей задачи запрещено триггером; статус меняется только через `transition_task`.
- Роли выдаются вручную через таблицу профилей, открытая регистрация не используется.

Перед публикацией проверьте SQL на тестовом Supabase проекте и создайте пользователей с обеими ролями.
